01 / Problem

A routed MoE reference materializes a large hidden tensor.

The approximate ragged_dot reference performs the expert up projection, materializes the full routed hidden matrix, applies GELU, and performs the down projection. The Pallas path instead visits hidden-dimension tiles and accumulates directly into the output.

02 / Design

Tile the expert hidden dimension and preserve FP32 accumulation.

01Stable route grouping and gather
02Load one hidden-dimension tile
03Up projection → GELU → down projection
04FP32 accumulation and scatter-add
  • FP16 and BF16 operands are preserved while both projections accumulate in FP32.
  • The complete routed hidden matrix is never materialized by the fused approximate backend.
  • Approximate execution is explicit because it changes activation semantics.
  • The custom VJP recomputes the matching JAX reference; backward is not a fused Pallas kernel.

04 / Scope and limitations

The result is shape- and semantics-dependent.

  • The fused backend uses approximate tanh GELU and must not silently replace exact-erf checkpoints.
  • Backward is a JAX/custom-VJP reference path, not a fused Pallas backward kernel.
  • The reported results are forward-layer measurements, not complete transformer-training speedups.
  • Small-route controls can lose even when the large routed workload wins.
