01 / Problem

Kernel performance needs a disciplined comparison contract.

A fast-looking number is not useful without a correct reference, explicit shapes and dtypes, a named baseline, synchronized timing, and profiler evidence. This repository organizes eight compact projects around that contract.

The projects cover row reductions, elementwise fusion, Tensor Core tiling, page tables, GQA/MQA, online softmax, E4M3 storage, hierarchical selection, routing, grouped GEMM, and out-of-tree operator registration.

03 / Evidence

Measurements are committed only after correctness passes.

The repository's evidence standard records the GPU and compute capability, driver and library versions, shapes, layouts, dtypes, tolerances, warm-up and measurement method, latency distribution, exact baseline, and profiler evidence for bottleneck claims.

Honest result policy: slower implementations remain visible. The vLLM integration is presented as a correct operator replacement, not automatically as a speedup.

04 / Scope and limitations

A laboratory, not a drop-in serving stack.

  • The NVIDIA L4 is the primary validation target; every architecture still needs its own run.
  • CPU checks validate references and packaging but do not compile or execute GPU kernels.
  • The repository does not claim to replace vLLM, SGLang, TensorRT-LLM, FlashInfer, cuBLAS, or CUTLASS.

05 / Repository

Self-contained projects and reproducible tooling.

Each project includes a focused README, correctness suite, and benchmark. Shared tools cover environment capture, PTX and SASS inspection, Nsight Systems, Nsight Compute, and result publishing.
