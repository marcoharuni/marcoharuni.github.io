ForgeEngine

A readable single-GPU Qwen3 inference engine with explicit prefill and decode, paged KV caching, continuous batching, custom kernels, and streamed chat.

01 / Problem

Make the serving path explicit.

High-level generation APIs hide the mechanisms that determine latency, memory ownership, batching behavior, and cancellation safety. ForgeEngine implements the path directly so each request can be traced through loading, prefill, decode, cache allocation, sampling, detokenization, and streaming.

Boundary: this is a focused, readable single-GPU engine for one pinned Qwen3 model revision—not a replacement for a production multi-model serving platform.

02 / Design

A bounded scheduler owns model execution and KV-cache mutation.

01Chat template and tokenization
02Bounded continuous scheduler
03Explicit prefill and decode
04Paged KV cache and streaming
  • Staged SafeTensors loading for the pinned model revision.
  • Separate prefill and token-by-token decode paths rather than model.generate.
  • Paged block allocation with deterministic release after completion, failure, or cancellation.
  • Greedy, temperature, top-k, top-p, and min-p sampling.
  • Triton residual/RMSNorm and CUDA paged-GQA paths with fallbacks.
  • Terminal, browser, and Rust SSE/load clients.

04 / Scope and limitations

What the current engine does not claim.

  • Only the pinned Qwen3 4B Instruct revision is supported.
  • Execution is one process on one NVIDIA CUDA GPU.
  • No distributed inference, quantization, speculative decoding, prefix caching, multimodal input, or non-NVIDIA backend.
  • The API does not provide built-in authentication, TLS, persistence, quotas, or multi-tenant isolation.
